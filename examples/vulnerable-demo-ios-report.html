M4 · Insufficient Input/Output Validation

Data from intents, URL schemes, WebViews or remote responses is trusted without validation, opening injection and code-execution surfaces.
Medium Application registers 2 custom URL scheme(s) IOS-CUSTOM-URL-SCHEME
M4 Insufficient Input/Output Validation CWE-939MASVS-PLATFORM confidence: Medium analyzer: ios_config
What was found
The app registers the custom URL scheme(s) `vulndemo://`, `vulndemo-auth://`. Any app or web page can open these URLs and control the parameters the app receives. iOS does not verify scheme ownership: another app can register the same scheme, and if it is installed second the system's choice of handler is undefined — which is the basis of URL-scheme hijacking against OAuth callbacks.
How to fix it
Validate and canonicalise every parameter arriving through `application(_:open:options:)`, and check the `sourceApplication` where it matters. For authentication callbacks use Universal Links bound to a domain you control, or `ASWebAuthenticationSession`, rather than a custom scheme.

M5 · Insecure Communication

Traffic that is unencrypted, or encrypted with validation disabled, can be read or modified by anyone on the network path.
Medium App Transport Security is disabled globally IOS-ATS-ARBITRARY-LOADS
M5 Insecure Communication CWE-319MASVS-NETWORK confidence: High analyzer: ios_config
What was found
`NSAllowsArbitraryLoads` is true, which switches off ATS for every connection the app makes: cleartext HTTP is permitted, and TLS connections no longer have to meet the minimum version and cipher requirements ATS enforces. Exception domains are also declared, so on iOS 10+ the global flag is ignored for those specific domains — but it still applies to everything else.
How to fix it
Remove `NSAllowsArbitraryLoads` and serve every endpoint over TLS 1.2+. Where one legacy host cannot be fixed yet, add just that host under `NSExceptionDomains` — App Review requires a justification for the global flag in any case.

M10 · Insufficient Cryptography

Broken or misused cryptographic primitives that fail to provide the confidentiality or integrity the app relies on.
High Block cipher used in ECB mode CRY-ECB-MODE
M10 Insufficient Cryptography CWE-327MASVS-CRYPTO confidence: High analyzer: crypto
What was found
A cipher is configured for ECB mode. ECB encrypts identical plaintext blocks to identical ciphertext blocks, so structure in the data survives encryption. The classic demonstration is an encrypted bitmap in which the original image is still recognisable. ECB also provides no integrity, so an attacker can reorder or replay blocks.
How to fix it
Use GCM, which provides both confidentiality and integrity, with a unique nonce per encryption. If GCM is unavailable, use CBC with a random IV and authenticate the ciphertext with a separate HMAC key.

Medium Weak hash algorithm in use: SHA1 CRY-WEAK-HASH-SHA1
M10 Insufficient Cryptography CWE-328MASVS-CRYPTO confidence: Medium analyzer: crypto
What was found
The package requests `SHA1`. SHA-1 collisions are practical (SHAttered, 2017). This matters wherever the hash is relied on for integrity or identity — signature verification, tamper checks, deduplication of security-relevant data. It is not a problem where the hash is only a non-security checksum or cache key, so confirm how it is used.
How to fix it
Use SHA-256 or SHA-3 for integrity and identity. For password storage no plain digest is appropriate — use Argon2id, scrypt or PBKDF2 with a per-user salt and a high iteration count.

How the risk score is calculated
Each finding contributes its severity weight (Critical 10, High 7, Medium 4, Low 1.5, Info 0) multiplied by a confidence factor (High 1.0, Medium 0.7, Low 0.4). A single rule contributes at most three times its unit weight, so one noisy rule cannot dominate. The total is mapped to 0-100 through 100 x (1 - e^(-total/30)), which saturates: the score is a communication device for ordering and triage, not a measurement of real-world risk.
What this analysis does not cover
This is static analysis only: the package was decompiled and pattern-matched, never executed. It cannot observe runtime behaviour, actual network traffic, server-side controls, or logic that is assembled dynamically or loaded after install. Native libraries, obfuscated code and reflective calls limit what static rules can see. Absence of a finding is not evidence of absence of a vulnerability.
